### Findings

#### SEV-1 · Responsive collapse (dashboard unusable below ~1100 px)

**Root cause:** the major grid layouts have no `@media` breakpoints,
so every multi-column row stays horizontal even at 430 px. The
result on mobile: each "column" gets crushed to ~80 px wide and text
becomes near-illegible.

| ID | Section | Element | Current behavior < 1100 px | Required behavior |
|---|---|---|---|---|
| R1 | Hero | `.hero` `grid-template-columns: 0.85fr 1.15fr 0.85fr` | All three cols stay side-by-side, Edge Score gauge gets crushed | Stack vertically: tier card → headline → Edge Score (or 1-col with headline on top) on tablet, 1-col on mobile |
| R2 | Scoreboard | `.scoreboard` `repeat(5, 1fr)` | 5 cells become 5 tiny columns | 2-col grid on tablet, 1-col on mobile (with borders adjusted) |
| R3 | Highlight reel | `.reel` `repeat(3, 1fr)` | Three video tiles squeeze to ~140 px each on mobile | 1-col on mobile (vertical scroll) |
| R4 | Swing of Week + DNA | `.two-col` `1.5fr 1fr` | DNA radar gets crushed under hero card | Stack: SoW card → DNA radar card on tablet & mobile |
| R5 | Form & Timing | `.diamond-row` `1fr 1.4fr` | Form Quadrants crammed next to Phase Timing | Stack on tablet & mobile |
| R6 | Phase Clock signature | `.signature` `1.1fr 1fr` | Dial gets clipped on tablet | Stack on tablet (meta above, clock below) |
| R7 | 12-Week stats | `.progress-stats` `repeat(6, 1fr)` | 6 stats become unreadably narrow | 3×2 on tablet, 2×3 on mobile |
| R8 | Milestones row | `.milestones-row` `repeat(4, 1fr)` | 4 badges squeeze | 2×2 on tablet, 1-col on mobile |
| R9 | Drill prescription | `.coach-grid` `repeat(3, 1fr)` | Drill cards become tiny | 1-col on mobile |
| R10 | Achievements rail | `.rail` `repeat(4, 1fr)` | 4 medals squeeze | 2×2 on tablet, 1-col on mobile |
| R11 | Pricing band | `.tiers-row` (3-col) | 3 cards squeeze | 1-col on mobile (already 2-col when only Family + Coach offered, but never collapses) |
| R12 | Footer | `.footer` `1fr 1fr 1fr` | Quote gets truncated | Stack on mobile |
| R13 | Editorial spine | `.spine` (left-edge running numbers) | Overlaps content on screens < 1280 px | Hide below 1280 px |
| R14 | Masthead nav | `.nav` (5 pill links) | Wraps badly on mobile | Hide on mobile, show hamburger or just logo |

**Severity reasoning:** SEV-1 because below ~1100 px the dashboard is
not just imperfect — it's nearly unusable. Roughly half of all
real-world traffic to a baseball app would be from phones (parents
watching from the stands, players checking results post-game).

#### SEV-2 · Desktop polish (mostly clean from prior pass)

| D3 | Trend chart annotation pins | The 3 PR annotation pins at top (`▲ PR 76% MATCH` etc) sit very close together on the right side | Spread evenly or reduce font size |

visible (swing count + top-metric + mood hidden to save room) — that's
intentional and works.

ideal but acceptable; a true responsive multi-line chart would require
re-computing coordinates per viewport which is out of scope for this
polish loop.

## How to run the loop again

```bash
# Critic — baseline
.venv/bin/python scripts/visual_qa/capture.py --label before-pass-N

# Reviewer fills VISUAL_QA_REPORT.md with new findings

# Fixer edits mock_dashboard_template.py / dashboard_v3.py

# Critic — after
.venv/bin/python scripts/visual_qa/capture.py --label after-pass-N
```

The `.visual_qa/` directory is gitignored — screenshots are local
artifacts; only `VISUAL_QA_REPORT.md` ships in commits.
